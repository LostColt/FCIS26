Build one small thing.

FCIS 2026 · Working guide · reviewed November 3, 2026

Start with something you or your students need. Make a first version. Try it. Ask for one change. You do not need to learn every tool on this page.

Choose where to start
  • Gemini Canvas: easiest first build
  • Share it or try Google Sites
  • Build on a Google Sheet
  • ChatGPT Sites
  • Advanced: code, GitHub and Vercel
  • Classroom and student-data checks

1. Build in Gemini Canvas

A useful first project: a reading companion that lets the learner hear a short passage and adjust how it is shown. Use an original or public-domain sample passage, not real student work.

  1. On a computer, open Gemini and sign in with an account that permits Canvas.
  2. Choose Canvas in the prompt tools. The location of this control may change.
  3. Copy the starter prompt below, replace any bracketed details, and send it.
  4. Use the preview. Try the buttons, tab through the controls, and check how it looks on a narrow screen.
  5. Ask for one change. Try the changed version again before sharing.
Build a one-page reading companion with a place to paste a short sample passage. Add optional read-aloud with start, pause and replay; adjustable text size and spacing; and a distraction-reduced reading view. Keep the original passage unchanged. Provide clear keyboard controls and an example passage clearly marked “Sample.” Make it usable on a Chromebook and phone. No logins, external AI/API calls, or student data collection.

For another subject, browse the 20 classroom starters by grade and subject. A good modification prompt is: “Keep what works. Change just [one thing]. Show me how to test it.”

2. Share it. Google Sites is optional.

  1. In Gemini Canvas, look for Share & export → Share and review the information about the app before copying a link.
  2. Open the link in a separate browser session to see what a visitor will see. Check whether a school account blocks sharing.
  3. If you have a Google Site, open its editor, choose Insert → Embed, and try the app URL. Some websites block embedding; if it fails, insert a clearly named link or button to the shared app instead.
  4. Publish the Google Site and test both the Site link and the app link as a visitor.

Important: Google Sites does not automatically host the code from a Gemini Canvas app just because you insert its shared link. An embedded URL may be blocked. A link that opens the app separately is a valid classroom solution. Google notes that some external pages cannot be embedded.

Sharing privacy: Canvas apps can have persistent or shared data. Google warns that anyone with a public link to a multi-user app can view or edit shared app data. Do not put student information in public demos or use them as a gradebook.

Sources: Gemini Canvas help · Canvas safety · Google Sites embedding

3. Start with a Google Sheet

If you already keep a schedule, inventory or assessment calendar in Sheets, the next tool may be a clearer view of what you already have. Use fictional rows for practice.

Option A — Sheets canvas, where available

  1. Open a Google Sheet in a desktop browser. Use made-up column headings such as Date, Grade, Course, Type.
  2. When your account has access to Sheets canvas, ask it to create a view of those rows. For example, “Show assessments by week. Flag days with more than one major assessment for the same grade.”
  3. Try changing a sample row. Confirm that the view reflects the changes and that the sharing permissions are appropriate.

Sheets canvas is not enabled for every account and may depend on your school’s Workspace plan or admin settings. Do not promise participants they will see it.

Option B — Google Apps Script

Apps Script can create a custom interface linked to a teacher's own Sheet. It is more technical and should be optional. The sample Assessment Calendar includes an offline demo and a “Use with Google Sheets” panel with Code.gs setup instructions. Test any deployment with fictional data and restrict access as school policy requires.

Sources: Sheets canvas help · Apps Script web apps.

4. Another starting point: ChatGPT Sites

Sites can create and host an interactive website in one workflow. Availability, publishing and sharing depend on plan and school workspace settings.

  1. In ChatGPT on web, use Work and describe the website, or mention @Sites if available.
  2. Describe the learner, the problem and the required interactions. Ask for fictional example content and no real student data.
  3. Review the private preview. Check buttons and mobile layout. Ask for one revision.
  4. Deploy only when ready, then explicitly review Share permissions before inviting others. New Sites are not necessarily public.
Build a simple interactive website for [grade/subject]. Students need to practice [one concept]. Include [two specific actions], clear directions and a sample exercise. The site should work on a Chromebook or phone and not collect student identities. Keep all examples fictional. Give me a preview to test before publishing.

Source: ChatGPT Sites help.

5. When you want something more complex

This is not required for the workshop. Use it if your tool needs multiple pages, complex interactions or ongoing code changes.

  1. Choose a builder. Google AI Studio can help prototype. Codex, Claude Code and Antigravity are coding environments or agents that can work with project files. You only need one; the exact controls differ.
  2. Describe a small first version. Specify pages, interactions, devices, accessibility and where data should live. Ask the coding tool to explain its file structure.
  3. Test locally. Open the project, try the main tasks and fix errors. For simple HTML projects, a small local server may be sufficient. Do not add real student records.
  4. Store the source in GitHub. Create a private repository, upload or commit the project files, and review the changes. Do not commit passwords, API keys or sensitive files.
  5. Host a compatible project with Vercel. Import the GitHub repository in Vercel, choose the correct framework or root directory, review environment variables, and deploy a preview.
  6. Check the public experience. Test the live link on mobile and in a signed-out browser. Verify data permissions before making it available to others.

For a static HTML site like this FCIS deck, Vercel can serve the website directly. Apps needing databases or login require additional design and access controls. Hosting and limits vary by provider and plan; school use may have account-policy implications.

Starting points: Google AI Studio · GitHub · Vercel documentation.

Before you share with students

Use mock information during development. Check AI-generated explanations, answer keys and links. Never submit names, grades, essays or student records to unapproved services. Check who owns the account, where information is stored, who can see it, and who maintains the tool later. Keep your LMS and gradebook as the systems of record.

When building reading supports, give learners choices rather than assuming one setting helps everyone. Read-aloud, spacing, contrast and focus views can be useful options, but they do not replace structured literacy instruction or school accommodations.

Start small. Let one colleague try it. Keep what works, and revise the rest.
