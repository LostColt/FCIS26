Questions before you build

Start with a need, not a product idea. Ask students what is difficult instead of assuming.

Ask your students

  • What part of this activity is hardest to start?
  • Where do you lose track or get stuck?
  • What would help you work more independently?
  • Is something about our process getting in the way of learning?

Ask yourself

  • What takes my attention away from students?
  • What do I repeatedly struggle to organize, remember, or keep up with?
  • What do I wish the tools I already use did differently?
  • Where could a small change give me more time to be present?

Before building anything

  • Who needs this: me, a student, a class, or a colleague?
  • Could an existing tool or a simpler change solve it?
  • What is the smallest version worth trying?
  • Can I test it with invented data, without collecting sensitive student information?
  • How will I know it actually helped?

You do not need to launch or sell an app. Build what helps you and those around you, and share how you worked through the problem.

Before you start

What you need, and the words you'll see.

Accounts

  • A Google account, school or personal. For Gemini, Google AI Studio and Sheets.
  • A paid ChatGPT plan, only for All in ChatGPT.
  • GitHub and Vercel, both free, only for Own it end to end: github.com/signup, then sign up at vercel.com/signup with GitHub.

Words you'll see

Prompt
What you type to describe the tool. Write it the way you'd explain it to a colleague.
Preview
The working version beside the chat. Try it there, the way a student would.
HTML
The file a web page is made of. One file can be a whole small tool.
Canvas
The panel where Gemini, or Google Sheets, builds and shows your tool.
Apps Script
Google's coding tool, built into Sheets, Docs and Forms (Extensions → Apps Script). It can turn a sheet into a small web app only your school can open.
Repository
A folder for your code on GitHub, with a history of every change.
Deploy, publish
Put it online so it has a link.

A first prompt that works anywhere

I teach [grade and subject]. My students struggle with [the problem]. Build a one-page app where they [what they do]. It must work on a Chromebook, need no login, and use large, readable text. Make it work without any AI or API calls. Don't collect names or any student data.

Start small, with no student information. Change one thing at a time. When it works, keep it; when it doesn't, say what's wrong in one sentence.

All in ChatGPT

If you already live in ChatGPT, you can stay there: build it, keep it and share it with a link, all in one place. Needs a paid plan.

  1. In ChatGPT, switch to Work. Sites lives there, not in regular chat.
  2. Type @Sites, or just ask it to build a website. Say who it's for and what it should do. You can attach files.
    Build a website for my 10th-grade biology class with this week's vocabulary as flip cards and a five-question self-check. Large, readable text. No logins.
  3. Try the preview. Ask for changes in plain language until it works the way you want.
  4. Publish it when it's ready. A new site starts private.
  5. Share it with specific people, or with anyone who has the link. More at chatgpt.com/features/sites.

Everything you put in it lives on OpenAI's servers. Keep student information out unless your school has an agreement that covers it.

Inside Google Workspace

If your school runs on Google, the data can stay where it already is. Two ways in: a quick tool in Gemini, or a dashboard on top of a Google Sheet you already keep.

A quick tool in Gemini

  1. Go to gemini.google.com and sign in.
  2. In the prompt bar, choose Canvas (it may sit under Tools or the + menu).
  3. Paste the first prompt from Before you start, fill in the brackets, and send it.
  4. Try it in the preview. Ask for one change at a time.
  5. Choose Share to get a link. On a school account you may also see Share to Classroom.

A shared Gemini link is a snapshot: after you change the tool, share again. Anyone with the link can open it. If your school has turned sharing off, ask your tech lead.

A dashboard from a Google Sheet

Start with a sheet your department already keeps: assessment dates, duties, hours, a sign-up list. The Assessment Calendar from the talk is a ready-made example: open it, or download it.

Option A, Sheets canvas (if your school has Gemini in Sheets):

  1. Open the sheet in your school account. Make a copy to practice on.
  2. Choose Insert → Create a canvas, or open the Gemini panel and choose Create canvas.
  3. Describe the dashboard:
    Make a board of our department's assessments grouped by week, so we can spot when three tests land on the same day for one grade.
  4. Use it. The canvas and the sheet stay in sync, and the canvas follows the sheet's sharing settings.

Option B, Apps Script (works on any Google account):

  1. Make a sheet with the headings Date, Grade, Course, Teacher, Type in row 1. To start from the sample, open the Assessment Calendar, choose Download as a sheet (CSV), then in Google Sheets File → Import → Upload.
  2. In the sheet, choose Extensions → Apps Script.
  3. In the Assessment Calendar, choose Use with Google Sheets. Copy Code.gs into Apps Script. Then add an HTML file named Index and paste in the whole dashboard.
  4. Choose Deploy → New deployment → Web app. Execute as: Me. Who has access: only people in your school. Click Deploy and approve the permissions.
  5. Share the link with your department. New rows in the sheet show up the next time the dashboard opens.

Google's own guide to Apps Script web apps: developers.google.com/apps-script/guides/web.

Own it end to end

The most hands-on way, and the most yours: the code lives in your own account, with a history of every change. It's how this site was built. Free to start.

  1. Prototype. Go to aistudio.google.com, sign in, and choose Build. Describe the tool with the first prompt from Before you start. Try it in the preview and ask for changes.
  2. Store. In AI Studio, open Settings → GitHub and create a new repository.
  3. Host. At vercel.com, choose Add New → Project, then Import next to your repository. If you don't see it, let Vercel see it when GitHub asks.
  4. Click Deploy. You get a link like your-tool.vercel.app.
  5. Change it any time: ask AI Studio for an edit and save it to GitHub. Vercel updates your link on its own.

If the deploy fails, ask AI Studio: "Make this a simple static site with no server, so it deploys on Vercel." Keep your first tool free of AI features; those need an API key and can cost money.

For your school

One teacher can build a tool in an afternoon. A school decides what it keeps. A school-managed, paid account (Google Workspace, ChatGPT for education) means the school can see the data, review it with committees and make decisions together.

Four questions to ask

  1. Who owns the account? A person's personal account leaves when they do. A school account stays.
  2. Where does the data live? In the browser, in the school's Google account, or on a company's servers? Each answer has different rules.
  3. Who reviews it? Name the people, or the committee, who look at new tools before students use them.
  4. How do we decide what we keep? Some tools are for one unit. Some become how the school works. Decide on purpose.

Build boldly. Not carelessly.

  • No student names, grades or work in a prompt or an app unless your school has approved that tool for it.
  • Follow your school's policy. Ask your tech lead before, not after.
  • Check the content yourself. AI-built tools can be confidently wrong.
  • Name an owner. Who fixes it in June? If nobody, keep it small.
  • Keep the systems of record (your LMS, gradebook, student information system) where they are. Build the small, specific things around them.
