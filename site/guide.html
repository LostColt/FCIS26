Build one small thing.

FCIS 2026 · Working guide · updated November 3, 2026 · account-specific controls may vary

Start with something you or your students need. Make a first version. Try it. Ask for one change. You do not need to learn every tool on this page.

1. Build in Gemini Canvas — one prompt

Slide 19 shows one user message revealed in sections, not a series of imagined replies from Gemini. Select Canvas before giving the prompt. Explain what you want, ask Gemini to make its own more detailed instructions, and ask it to use those instructions to build. Your account and Gemini's response may vary.

The complete example prompt

I want a futuristic interface with a moving particle shape in the middle. I want to move it with my mouse and see computer panels around it.

Turn what I just described into a detailed build prompt for yourself. Include the design, movement, interactions, and things I might have missed.

Then use that prompt to build the application in Canvas.

How the build works

  1. Open Gemini in an account where Canvas is available; select Canvas.
  2. Paste or adapt the single prompt above and submit it. The presentation reveals the text in stages only to make it easier to explain.
  3. Review the output. If Gemini wants clarification or proposes a different approach, respond based on what you actually see. A specific result is not guaranteed.
  4. Try the preview, request one change in ordinary language, and test the revision.
  5. Keep your source: copy the code if available, download an export where supported, and open the resulting app to test it independently. Controls may vary by account, platform and output type.

The interactive HUD example is an existing HTML file, not a live Gemini response. The presentation's Copy code, Download HTML, and Open app controls operate on that actual demo file. You can also download the example HTML from this resource page.

For a classroom example, use the 20 subject- and grade-specific starters. Keep student information out of unapproved services.

2. Export to Google Sites, then publish

The screenshots in the presentation show the real controls: in Gemini Canvas choose Export → Google Sites, then use the Google Sites editor to review and publish the page. This direct export creates a new private draft; it does not automatically make the page public. The school Google Workspace account shown here is a useful demonstration, but Google also lists personal Google accounts and Workspace Individual among eligible users. Controls and permissions may differ.

  1. Once the interactive app works in Gemini, choose Export → Google Sites on the app.
  2. Google Sites opens a new private draft with the interactive app included. Review the result, title and page layout.
  3. Choose Publish in Google Sites. Review the site's web address and sharing/audience settings before confirming.
  4. Open the published address in another browser session, ideally signed out, to verify what visitors can actually access.

Important: Export does not automatically make the site public. This route requires Google Sites access and permission to create and edit sites; organizational Google Drive and Sites policies still apply. If Export → Google Sites is unavailable in your account, look for Export → Download code in Canvas (as shown in the workshop screenshots). You can save the HTML and use a school-approved hosting method, or share the Canvas link where permitted.

Data: Use invented examples for demonstrations. Shared Gemini apps may have stored or shared data, so review settings carefully and do not use an experimental public app for student records.

Sources: Google Workspace announcement, October 19, 2026 · Gemini Canvas help · Google Sites help

3. Start with a Google Sheet

If you already keep a schedule, inventory or assessment calendar in Sheets, the next tool may be a clearer view of what you already have. Use fictional rows for practice.

Option A — Sheets canvas, where available

  1. Open a Google Sheet in a desktop browser. Use made-up column headings such as Date, Grade, Course, Type.
  2. When your account has access to Sheets canvas, ask it to create a view of those rows. If you do not see that feature, use the sample dashboard without connecting school data. For example, “Show assessments by week. Flag days with more than one major assessment for the same grade.”
  3. Try changing a sample row. Confirm that the view reflects the changes and that the sharing permissions are appropriate.

Sheets canvas is not enabled for every account and may depend on your school’s Workspace plan or admin settings. Do not promise participants they will see it.

Option B — Google Apps Script

Apps Script can create a custom interface linked to a teacher's own Sheet. It is more technical and should be optional. The sample Assessment Calendar includes an offline demo and a “Use with Google Sheets” panel with Code.gs setup instructions. Test any deployment with fictional data and restrict access as school policy requires.

Sources: Sheets canvas help · Apps Script web apps.

4. Another starting point: ChatGPT Sites

Sites can create and host an interactive website in one workflow. Availability, publishing and sharing depend on plan and school workspace settings.

  1. In ChatGPT on web, use Work and describe the website, or mention @Sites if available.
  2. Describe the learner, the problem and the required interactions. Ask for fictional example content and no real student data.
  3. Review the private preview. Check buttons and mobile layout. Ask for one revision.
  4. Deploy only when ready, then explicitly review Share permissions before inviting others. New Sites are not necessarily public.
Build a simple interactive website for [grade/subject]. Students need to practice [one concept]. Include [two specific actions], clear directions and a sample exercise. The site should work on a Chromebook or phone and not collect student identities. Keep all examples fictional. Give me a preview to test before publishing.

Source: ChatGPT Sites help.

5. When you want something more complex

This is not required for the workshop. Use it if your tool needs multiple pages, complex interactions or ongoing code changes.

  1. Choose a builder. Google AI Studio can help prototype. Codex, Claude Code and Antigravity are coding environments or agents that can work with project files. You only need one; the exact controls differ.
  2. Describe a small first version. Specify pages, interactions, devices, accessibility and where data should live. Ask the coding tool to explain its file structure.
  3. Test locally. Open the project, try the main tasks and fix errors. For simple HTML projects, a small local server may be sufficient. Do not add real student records.
  4. Store the source in GitHub. Create a private repository, upload or commit the project files, and review the changes. Do not commit passwords, API keys or sensitive files.
  5. Host a compatible project with Vercel. Import the GitHub repository in Vercel, choose the correct framework or root directory, review environment variables, and deploy a preview.
  6. Check the public experience. Test the live link on mobile and in a signed-out browser. Verify data permissions before making it available to others.

For a static HTML site like this FCIS deck, Vercel can serve the website directly. For a working sample, review the site and guide, then change one feature before attempting to deploy your own project. Apps needing databases or login require additional design and access controls. Hosting and limits vary by provider and plan; school use may have account-policy implications.

Starting points: Google AI Studio · GitHub · Vercel documentation.

Before you share with students

Use mock information during development. Check AI-generated explanations, answer keys and links. Never submit names, grades, essays or student records to unapproved services. Check who owns the account, where information is stored, who can see it, and who maintains the tool later. Keep your LMS and gradebook as the systems of record.

When building reading supports, give learners choices rather than assuming one setting helps everyone. Read-aloud, spacing, contrast and focus views can be useful options, but they do not replace structured literacy instruction or school accommodations.

Start small. Let one colleague try it. Keep what works, and revise the rest.
